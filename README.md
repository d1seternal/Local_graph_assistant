# Локальный ассистент для работы с документами

Проект представляет собой локальное ИИ-приложение для поиска информации и получения ответов по документам формата TXT, PDF и DOCX. Документы, индексы и модели размещаются на компьютере пользователя. После первоначальной установки зависимостей и загрузки моделей далее приложение предназначено для работы в режиме оффлайн.

В основе используется RAG: приложение извлекает текст, разбивает его на фрагменты и сохраняет их эмбеддинги. При вопросе выполняется семантический поиск по выбранной доступной коллекции, после чего найденный контекст передаётся небольшой локальной языковой модели, запусаемой через сервис Ollama. Вместе с ответом возвращаются использованные фрагменты и сведения об их источниках.

Цель проекта: получение понятной и безопасной среды с воспроизводимым локальным запуском, минимальным использованием ресурсов (в пределах тех, которые имеются на вашем собственном ноутбуке), матрицей прав пользователей и протоколом измерений.


## Первый запуск:

Команды выполняются из корня репозитория после клонирования. Целевое окружение
проекта — **CPython 3.13.5, arm64**, все описанные дальше зависимости загружаются через менеджер pip. Установщик доступен с официального сайта Python.
Для первоначальной установки пакетов и скачивания моделей нужен Интернет.

**1. Установка зависимостей**

```bash
python3.13 -c 'import sys, platform; print(sys.version.split()[0], platform.machine())'
python3.13 -m venv .venv
source .venv/bin/activate
python -m pip install --only-binary=:all: -r requirements.txt
python -m pip check
```

**2. Загрузка моделей**

Установить [Ollama](https://ollama.com/download).
Запустить в отдельном терминале через `ollama serve`. В терминале проекта:

```bash
ollama pull qwen2.5:3b
ollama list
python -m app download-e5
```

Qwen хранится в каталоге моделей Ollama. Приложение обращается к ней через `http://127.0.0.1:11434/api/chat`. E5 скачивается в `models/embeddings/multilingual-e5-small/` с весами safetensors, конфигурацией и токенизатором. При замене состава файлов модели прежние индексы могут потребовать переиндексации.

**3. Создание БД и аккаунта**

```bash
python -m app init-db
python -m app.create_user demo --role user
```

Первой командой создаются таблицы в `data/app.sqlite`; второй — аккаунт и его
личная коллекция. В существующей установке аккаунт повторно создавать не нужно. Файлы пользователей сохраняются
в `data/documents/`.

**4. Запуск приложения**

```bash
python -m app serve
```

Необходимо будет открыть указанный адрес и войти под созданным профилем. Далее доступные функции будут указаны на странице приложения. Для отладки API остаётся доступен запуск напрямую:
`python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1`.

## Матрица прав

| Операция | Администратор | Разработчик | Пользователь |
| --- | --- | --- | --- |
| Управлять пользователями и ролями | Да | Нет | Нет |
| Настраивать модель, очередь и лимиты | Да, при наличии доступа к среде выполнения | В среде разработки | Нет |
| Изменять код приложения | При наличии отдельного доступа к коду | В среде разработки | Нет |
| Назначать доступ к общим и тестовым коллекциям | Да | Нет | Нет |
| Загружать документы | В разрешённые коллекции с правом write | В явно разрешённые тестовые коллекции с правом write | В личную; в назначенные коллекции с правом write |
| Искать и читать данные документов | В разрешённых коллекциях с правом read | В явно разрешённых тестовых коллекциях с правом read | В личной; в назначенных коллекциях с правом read |
| Удалять документы | В разрешённых коллекциях с правом manage | В явно разрешённых тестовых коллекциях с правом manage | В личной; в назначенных коллекциях с правом manage |
| Запускать повторную индексацию | В разрешённых коллекциях с правом write | В явно разрешённых тестовых коллекциях с правом write | В личной; в назначенных коллекциях с правом write |
| Просматривать ответы и историю запросов | Свои запросы, с учётом текущего доступа к источникам | Свои тестовые запросы, с учётом текущего доступа к источникам | Свои запросы, с учётом текущего доступа к источникам |
| Отменять запросы | Свои запросы | Свои запросы | Свои запросы |
| Просматривать журнал | Технические события без автоматического доступа к содержимому чужих документов | Журнал среды разработки | События своих запросов |

### Правила применения

- Доступ определяется ролью, типом коллекции и назначенным уровнем прав.
- Уровни наследуются: manage включает write и read; write включает read.
- Личная коллекция доступна только владельцу. Роль администратора не открывает чужие личные коллекции.
- Разработчик получает доступ только к явно разрешённым тестовым коллекциям.

## Автоматические тесты

В отдельной виртуальной среде можно проверить API и отказы:

```bash
python -m pip install -r requirements.txt
python -m pip check
python -m unittest discover -s tests -v
```

Запуск тестов по отдельности:
```bash
python -m unittest tests.test_user_flow -v
python -m unittest tests.test_deadlines -v
```

Тесты используют временные БД/файлы. Проверяются Bearer-сеанс, границы коллекций,
загрузка, дедупликация, парсинг, настройки, атомарность индекса и тайм-ауты
дочерних процессов. Для генерации используются тестовые модели и HTTP-заглушка.
